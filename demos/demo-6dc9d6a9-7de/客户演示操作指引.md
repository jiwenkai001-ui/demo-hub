# 客户演示操作指引（V2.2）

## 开始前

双击“启动演示.cmd”，确认总入口右侧显示实时同步。若提示旧版服务，请关闭原启动窗口后重新启动。商户演示账号 admin / 123456（自定义环境口令除外）。

可先运行 `python 演示前检查.py --save`，检查服务版本、两店状态及页面资源，不会取号、叫号或清空。Python不在PATH时，可使用安装的Python完整路径运行。

同一台电脑打开顾客端、商户端和大屏，选择同一门店。两部手机演示时连接同一可互通Wi-Fi；顾客扫码，店员从总入口打开商户端。实际试听一次语音，并避免电脑休眠。

## 建议的7步演示

1. 商户登录。若需要从H001开始，在门店设置选择“重新开始演示”，核对清空范围后确认；确保开放取号。只清今日不会重用已有号码。
2. 顾客端取号，展示号码、服务类型、完整时间和前方人数。刷新同一浏览器，确认仍是原号。
3. 用另一浏览器或另一台手机取第二个号，展示前方人数。一个浏览器多个同店标签是同一设备，不应重复取号。
4. 商户点击叫下一位，观察顾客和大屏更新。点击重呼可再次播报；语音需先手动开启，每店只允许一个播报终端；切换时先关闭原终端语音。
5. 将当前顾客过号，切到过号队列指定重呼，再完成。展示工作台“已完成记录”，以及顾客已完成状态。
6. 切到号单档案，按日期/状态筛选、翻页和导出CSV；回工作台继续叫下一位。
7. 暂停新取号、修改公告/时长，观察顾客同步；已有号仍可继续服务。结束前恢复开放状态。

## 遇到提示时

| 提示或现象 | 处理 |
|---|---|
| 当前顾客尚未结束，不能叫下一位 | 先完成或过号当前号；这是接待规则 |
| 登录失效 | 重新登录；号单不会因此清空 |
| 连接中断、暂时不可用 | 检查服务窗口和网络，点重新连接；恢复后继续，不反复点击业务动作 |
| 号单刚被处理 | 系统已刷新最新状态，确认号码后再操作，避免两位店员同时处理 |
| 手机打不开二维码地址 | 用同一Wi-Fi，修正总入口手机访问地址；允许Python接收网络连接，检查访客隔离；手机不能访问电脑的127.0.0.1 |
| 语音或复制受浏览器限制 | 页面号码和业务仍可使用；语音在支持的浏览器手动开启；链接可从二维码下方直接打开或复制 |
| 重启后没有演示顾客 | 清空状态会被保留；用“添加演示顾客”补充，不需要删除数据库 |

当前软件已完成79项自动化验收，详见[V2.2验收报告](V2.2优化实施与系统验收报告.html)。手机扫码、实际扬声器及现场网络仍应按以上流程当场确认。


## 新版体验功能演示

1. 在设置中按需启用到场确认（须当前无人接待），说明默认仍是直接叫号；有号时展示“确认到场并服务”。
2. 准备两张等待号，先叫第一位，再点“完成并叫下一位”，确认号码对应关系后提交。
3. 独立过号后15秒内点撤销；演示后续叫下一位时不再允许撤销，避免改变已推进的接待顺序。
4. 在过号顾客页点“我已到店”，在商户过号列表查找其号码并重呼；不会自动插入等待队列。
5. 用“现场代取号”为无法扫码顾客正常排队，号码弹窗给顾客查看；本轮不连接打印机。
6. 顾客点取消并确认，展示已取消及30秒冷却；该号留在档案，不计完成。
7. 试用号码搜索、日期范围、来源筛选及CSV；手机列表可展开完整信息，低频二维码/演示工具也可展开。

本轮继续保留每店一个接待位。署名只是操作记录，不能当作多店员权限；短信和后台锁屏推送未接入。
