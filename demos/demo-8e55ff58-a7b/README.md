# 云裳序 · 排队叫号系统（重构版 Demo）

**当前版本：V2.2（2026-10-22体验优化），79项自动化验收全部通过。** 详见[本轮优化与系统验收报告](V2.2优化实施与系统验收报告.html)。V2.1的53项及40项功能保留表为历史基线，本轮继续纳入原功能回归。

本目录是一套可独立运行的全新演示系统：总入口、顾客取号、商户工作台、门店大屏共用一个真实的 Python + SQLite 服务。运行不需要 npm、构建工具或第三方 Python 包。原 Demo 源码快照和历史分析文档保留在上一级目录。

## 启动与访问

1. 安装 **Python 3.10 或以上版本**。当前电脑已安装 Python 3.13，可直接运行。
2. 双击本目录的 **启动演示.cmd**。脚本自动寻找 Python、检查端口、启动服务并打开浏览器。
3. 保持启动窗口打开，访问 [总入口](http://127.0.0.1:8800/)。停止时按 `Ctrl+C` 或关闭启动窗口。

| 页面 | 默认地址 | 用途 |
|---|---|---|
| 总入口 | http://127.0.0.1:8800/ | 选择角色、门店，获取扫码地址 |
| 顾客端 | http://127.0.0.1:8800/customer.html | 取号、恢复我的号单、查看进度 |
| 商户端 | http://127.0.0.1:8800/merchant.html | 登录、叫号、过号、完成、档案、设置 |
| 门店大屏 | http://127.0.0.1:8800/display.html | 当前号、全量等待号码自动轮播、可选语音 |

**演示账号：admin　口令：123456。** 两家示例门店分别登录、分别保存数据。

请通过 HTTP 地址访问。直接双击 HTML 或使用普通静态服务器无法运行数据库接口。

命令行启动也可使用：

```powershell
python serve_demo.py --host 0.0.0.0 --port 8800 --seed-demo --open-browser
```

若 `python` 不在 PATH，使用 `py -3`，或使用启动脚本自动寻找已安装的 Python。

```powershell
.\start-demo.ps1 -Port 8801       # 更换端口
.\start-demo.ps1 -NoBrowser       # 不自动打开浏览器
.\start-demo.ps1 -NoSeed          # 首次启动不生成演示号单
```

首次空数据库启动时，默认生成西湖店 12 条演示号单（3 条完成、2 条过号、7 条等待），南门店为空。后续启动保留现有数据；手动清空后重启不会重新填样本。工作台“添加演示顾客”每次添加 6 位，不替换已有号单；“清空今日数据”需要二次确认，且**不重用今日已分配的号码**。

## 推荐演示流程

1. 打开总入口、商户工作台和门店大屏，选择相同门店。
2. 若要从空队列演示，在工作台的“门店设置”中清空今日数据，或选择尚无数据的南门店。
3. 在顾客端取号；刷新或重新打开同一浏览器的顾客页，号码会恢复。另一浏览器或手机可作为另一位顾客。
4. 商户点击“叫下一位”，顾客端和大屏同步更新。当前顾客必须先“完成接待”或“过号”，才可叫下一位。
5. 在“过号队列”中点击“重呼该号”，重新接待；完成后，顾客可再次取号。
6. 在“号单档案”按日期范围、状态、号码、来源筛选并翻页，导出真实 CSV 文件。
7. 修改接待时长、门店提示或停止新取号，观察顾客端更新。暂停取号不会阻止已有号单继续接待。

界面可切换中英文；同一门店同一部署目录的多个标签页会同步语言偏好。门店名称和店员填写的提示属于业务内容，保留原文。

## 手机扫码与局域网

服务默认监听 `0.0.0.0`。电脑与手机连接同一 Wi-Fi 后，总入口、工作台会根据电脑局域网地址生成本地二维码。二维码包含当前部署子目录和门店参数，全部在本地生成，无需访问第三方二维码服务。

如果电脑有多个网卡、自动选错 IP，可在总入口的“手机访问地址”输入正确地址，例如 `http://192.168.1.10:8800/`，再点“更新二维码”。Windows 防火墙需要允许 Python 在当前网络接收连接；网络的访客隔离也可能阻止手机访问。`127.0.0.1` 只能在当前电脑使用。

物理手机扫码、扬声器音量和特定浏览器语音包需在现场确认。本次验收覆盖二维码 SVG、目标路径、浏览器语音触发逻辑，未宣称验证过实际手机或扬声器。

## 已确定的业务规则

| 项目 | 新版规则 |
|---|---|
| 排队次序 | 服务端事务分配递增 sequence，所有页面和前方人数使用相同顺序 |
| 一个有效号 | 同设备、同店、同营业日，waiting / called / passed 合计最多一个有效号 |
| 完成后再取号 | 允许；完成号保留在历史中 |
| 当前接待 | 每家门店最多一位；必须明确完成或过号后才能切换 |
| 过号召回 | 不自动插回等待队列，由店员明确召回，要求当前接待为空 |
| 预计等待 | 前方等待人数 × 配置接待时长 + 当前接待预计剩余时长，取整且不小于零 |
| 营业日 | 统一使用北京时间 UTC+8；当某店跨日后首次读取/操作，旧的有效号过期，新日从 H001 开始 |
| 数据重置 | 今日清空保留历史及今日计数；重新开始演示清本店全部营业日并从H001重开，均二次确认 |
| 持久化 | SQLite，默认 data/queue.sqlite3；关闭或重启服务不会丢失数据 |
| 同步 | 可见页面约 1.5 秒轮询；失败约 4 秒退避；回到前台立即刷新；同源同店标签页另用广播加速 |
| 历史 / 大屏 | 档案每页 10 条、工作队列每页 8 条，大屏固定最近3位，其余每页9位、每8秒轮播，不截断历史 |
| 请求重试 | 写入带请求编号；网络失败重试仍使用同一编号，服务端去重；票据版本保护旧页面操作 |

设备标识是浏览器本地随机标识，不等同于真实手机号或身份认证。更换浏览器、无痕模式、清理存储会被视为新设备；同一浏览器的顾客页代表同一个人，需使用独立浏览器/手机模拟多人。

## 配置与部署目录

```powershell
# 可自定义演示口令（启动前设置）
$env:QUEUE_DEMO_PASSWORD = 'your-demo-password'
python serve_demo.py --port 8800

# 验证子目录部署；地址变为 http://127.0.0.1:8800/queue/
python serve_demo.py --base-path /queue/ --port 8800

# 使用其他数据文件
python serve_demo.py --db D:\demo-data\queue.sqlite3
```

每个部署应使用独立数据文件。浏览器存储键包含部署路径与门店，商户会话 Cookie 包含门店且限定部署路径。反向代理必须将同一前缀下的页面、静态资源和 API 一起转发，不能只发布 HTML 到 GitHub Pages。

本项目用于本地业务演示。已实现商户会话与服务端操作守卫；正式运营仍需按实际场景建设 HTTPS、账号体系、权限分级、数据库备份及运维监控。

## V2.1补充使用说明

- 工作台直接提供等待、过号、已完成三个标签，补齐服务类型、完整日期时间和过号次数；手机端也保留返回总入口、顾客端、退出和二维码。
- “重新开始演示”清空本店所有营业日的号单和记录，重置编号至H001；保留门店设置（暂停状态也保留）、登录和其他店数据。“清空今日数据”则保留今日计数和历史。
- 初始化失败、服务断线和档案读取失败可恢复；已验证旧库迁移、真实服务重启、并发处理和多端轮询。
- 演示前运行 `python 演示前检查.py --save`，无业务数据清理。现场流程见[客户演示操作指引](客户演示操作指引.md)。
- 旧版文档声明默认跨域；新版默认同源，保留 `python serve_demo.py --allow-cors` 可选接口演示模式，支持 CORS * / OPTIONS，不携带跨域会话凭据；商户端仍需登录。正常多手机访问同一个地址无需开启该模式。
- 本轮53项包括26项业务、5项HTTP、22项浏览器用例；1,000步随机流程是其中一项。当前服务12项自检单列。旧28项为2026-10-21 V2.0历史结果，保存在复核资料中。


## V2.2 新增操作

- 门店设置可选“叫号后确认顾客到场”，默认关闭；开启后先叫号再确认服务，到场前不能完成。
- “完成并叫下一位”会显示两张号码并在一个事务内完成；原独立操作保留。
- 独立过号/完成后15秒内且门店没有后续业务写入时可撤销；后续已推进则不可恢复。
- 工作台可现场代取、按号码查找，手机显示卡片。二维码与演示顾客工具在展开面板内。
- 顾客可取消等待/过号号单；取消后30秒不能重取。过号可告知“我已到店”，仍由店员安排。
- 每店只允许一个语音终端，其他端默认静音；关闭后可交接，离开页面最多等待12秒。
- 号单档案增加范围/号码/来源、平均首次等待、累计服务及过号占比，CSV按相同条件导出。
- 接待员署名是本浏览器的演示记录；多账号权限、多窗口并行接待、短信/小程序通知尚未接入。

本轮优化前程序和数据库备份见“优化资料”。历史号单没有完整服务分段数据，无法追补准确服务时长；新操作按累计服务段记录。
