# AI录单系统 · 重构演示版 V3

交付日期：2026-10-22。根据原版 Demo 源码和《业务与功能详细说明》V1.1重构，原版源码与分析文档保留在上级目录。本文件夹为独立运行的新系统。

## 1. 打开方式

**快速体验：双击 `index.html`。** 无需安装依赖或联网，可使用四行业全部案例、文字进件、解析、人工复核、新品建档、订单、CSV及备份。推荐使用新版 Edge 或 Chrome。

**完整演示：双击 `启动演示.cmd`。** 需要 Python 3.10或以上，启动后自动打开 `http://127.0.0.1:8765/`。增加SQLite保存、演示账号、并发版本检查、消息接收接口及可配置的附件识别接口。关闭命令窗口即停止服务。

也可在本文件夹执行：

```powershell
python server.py
# 如果8765被占用：
python server.py --port 8766
```

无需 npm、构建工具或数据库安装程序。`tests/`中的Playwright仅用于开发验收，运行系统不需要它。

## 4. 推荐演练

### 演练一：从异常到正式订单

1. 选“生鲜配送”，打开“锦华火锅”，点击“开始解析”。五行中四行自动匹配，冰鲜带鱼保留为未匹配、未定价。
2. 点击冰鲜带鱼的“＋新品待建”，填写商品编码、名称、单位“斤”和价格。提交建立真实商品档案，再核对该行并保存。
3. 点击“写入订单”。先生成草稿，原进件与订单按稳定ID关联。
4. 在订单中心点击“确认订单”；客户有效且所有明细已核对后变为已确认。
5. 点击“导出CSV”，可选择全量、当前筛选或已确认范围。
6. 修改数量或单价，该行回到待复核、订单回到草稿。点击“确认”完成明细核对，再确认整单。

如果把“10斤冰鲜带鱼”绑定到按“条”计价的鲈鱼，系统会要求手工补充条数，不会把10斤直接当成10条。候选商品只是建议，不能替代人工核实。

### 演练二：单位和包装换算

1. 切换“餐饮食材”，打开“满堂红酒楼”并解析。
2. “基围虾8斤”换为4kg，按88元/kg计算352元，并提示核对换算。
3. “嫩豆腐3箱”按1箱12盒换为36盒，小计126元；保留“请复核”提示。
4. 已计价合计为1798元。原版1777元来自豆腐被误填为30盒，已纠正。

在“商品资料”中维护 `箱=12`，含义是“1箱等于12个该商品的计价单位”。重量单位克、斤、kg、吨支持通用换算；箱、包、瓶等必须有该商品的换算关系。规格文案不被系统擅自当作换算承诺。

### 演练三：手工文字与原文溯源

点击“接收进件”，输入客户、日期和以下内容：

```text
客户：测试餐厅
番茄10斤，土豆一千斤，番茄10-20斤，10斤
明天送到
```

中文千位数正确转为1000；数量范围保持待补；只有“10斤”的片段要求补商品名称。所有疑点保留在解析结果中，不能静默漏行。纯文本中的“客户：名称”可提取客户，明天或周几可辅助填写交货日期；下单日期和具体交期可通过表单明确设置，仍需人工核对。

数字编辑使用严格格式：数量最多六位小数、单价最多两位小数。表格不接受 `1,000`、`12abc`、`Infinity`、科学计数法、负数或零数量；金额与数量上限为1000万。消息自然语言中的规范千位分隔数量会先归一化，不等同于表格数字录入规则。

### 演练四：删除、重录与行业保存

删除订单或清空当前行业工作台后，原始进件保留并恢复可录入。点击“撤销上次删除”恢复相关订单；最近十次删除/清空可逐次撤销。撤销会保留其后新增商品、进件及现有明细修正；若同一进件已经生成新订单，则保留新订单，避免双重录入。

行业切换保留各自数据，不清空订单。解析中切换行业或进件会取消旧任务，旧结果不会写到新客户或新行业。

## 5. 图片、语音和识别能力

内置图片纸单、语音转写使用原版预设案例，界面明确标记“内置演示案例”。可上传真实图片或音频；图片可预览，音频可播放，原始附件随工作空间保存。

- 单个附件最多8MB。图片支持PNG、JPEG、WebP、GIF；音频可选浏览器识别为音频的格式，播放能力取决于浏览器编码支持。
- 未配置服务时，可直接填写“识别文本/人工补录”，然后使用同一套解析、复核、录单流程。
- 语音输入按钮在浏览器支持且授予麦克风权限时调用浏览器语音识别；并非本系统内置的离线ASR。
- 连接本地服务并配置识别适配器后，上传无文字附件再点击解析，将真实调用适配器。失败时保留附件并提示错误，不用示例文字冒充识别结果。

### 识别适配器约定

启动前配置：

```powershell
$env:ZHILU_RECOGNIZE_URL = 'http://127.0.0.1:9000/recognize'
# 如果你的适配器要求Bearer令牌，再设置这一项：
$env:ZHILU_RECOGNIZE_TOKEN = '替换为你自己的服务令牌'
python server.py
```

该地址必须是你实际实现的OCR/ASR适配接口；任意第三方模型地址通常不能直接使用，需要按以下约定转换请求及返回值。密钥保存在启动进程的环境变量中，不写入前端。

服务端向适配器发送JSON：

```json
{
  "type": "image",
  "industry": "fresh",
  "attachment": {
    "name": "订单.png",
    "mime": "image/png",
    "data": "data:image/png;base64,..."
  }
}
```

语音的 `type` 为 `voice`。返回：

```json
{"text":"番茄10斤，土豆20斤"}
```

非空text最多50000字，调用超时45秒。得到文本后仍由本地规则和商品资料生成明细，包装、模糊品名及数量疑点仍须复核。本次验证用本机测试适配器核对了真实HTTP往返，未使用第三方付费服务或真实业务附件验收。

## 6. 接口进件

**无需服务：** 在“连接与设置”导入本目录 `接口进件示例.json`。支持单个对象或数组，每批最多1000条、文件最多5MB。`industry + externalId` 用于去重，导入后进入对应行业。

**服务推送：** `POST /api/inbox`，请求头 `Content-Type: application/json` 和 `X-Inbox-Token: 你的进件令牌`。首次运行自动生成令牌文件 `本地数据/inbox-token.txt`，也可使用 `ZHILU_INBOX_TOKEN` 环境变量指定。该文件不会被静态服务暴露。

请求体示例：

```json
{"industry":"fresh","externalId":"adapter-20261022-001","customer":"接口测试餐厅","sender":"采购员","source":"外部适配器","type":"text","content":"西红柿10斤，鸡蛋2箱"}
```

首次接收201；同一行业相同外部编号再次提交返回200、`duplicate:true`。页面点击收件箱右上角同步按钮后拉取新消息。推送只接收进件，不会自动绕过复核生成正式订单。

行业代码：`fresh`生鲜、`food`餐饮、`hardware`五金、`general`日用。也接受 `date`、`deliveryDate`。微信、企业微信等来源需外部适配器完成平台鉴权及消息转换；本演示没有预置或代申请微信应用凭据。

## 7. 保存、备份和多窗口

- 双击HTML：数据保存在该浏览器、该入口对应的localStorage。浏览器清理、无痕模式、换浏览器或移动文件可能导致原工作空间不可见；请下载完整备份迁移。
- 本地服务：SQLite保存在 `本地数据/workspace.sqlite3`，并保留浏览器副本。重新登录优先加载服务端工作空间；服务端首次为空时使用当前浏览器工作空间初始化。
- HTML入口、不同端口、不同浏览器的本地存储彼此独立。迁移使用完整备份，不会自动合并不同入口的数据。
- 每个行业独立保存商品、进件、订单和当前选中项；四行业共用审计日志及备份文件。演示账号操作同一工作空间，不是租户隔离系统。
- 服务端保存带版本号。两个窗口同时修改时，过期窗口收到冲突提示，停止继续覆盖；先下载本机备份，再刷新读取最新服务端状态，人工合并差异。
- 完整备份含商品、进件、附件、订单、复核、日志和撤销历史；CSV仅是订单明细，不可用于恢复工作空间。
- 恢复前检查备份结构、正式订单有效性和进件关联，并先下载当前工作空间备份；恢复会替换整个工作空间。
- 大附件可能超过浏览器localStorage容量。页面会明确提示保存失败；此时保留当前页并下载完整备份。运行本地服务可继续保存SQLite，但不要忽略保存状态提示。
- “已计价合计”只累计已绑定有效商品、数量和价格完整且计价单位正确的行。未定价不是0元，不计入金额；待复核但字段有效的草稿行可计入已计价合计，合计并不表示全部为正式订单。
- 全量CSV保留原功能；包含待处理项时需明确勾选允许导出草稿。正式导出可选“仅已确认订单”，文件保留订单状态、复核状态、原文、进件ID、来源、发送人等字段。

完整结论、34项原功能对应表、15类修复和客户演示顺序见 [新旧功能核对与系统验收报告](新旧功能核对与系统验收报告.html)。本轮274项功能、数据及交互检查和37组页面弹窗布局检查通过，覆盖320、390、768、1440px场景；具体设备和验收范围见报告。

- 订单客户单元格可逐行修改；“修正”窗口的明细客户留空表示继承整单客户。整单编辑不覆盖已经指定的行客户。分组、搜索和CSV均以各行实际客户为准。

## 11. 体验优化版操作

最新完成情况和全套回归数字以 [体验优化与验收报告](体验优化与验收报告.html) 为准。旧章节中的274项、37组为上轮结果；最新报告已包含本轮体验专项。

- 刷新页面载入新脚本；若Python本地服务此前已经启动，请先停止并重新运行“启动演示.cmd”，服务需要允许新增的ux.js、xlsx.js资源。原V3本地数据和备份可继续使用。
- 页面业务概览默认收起，可展开查看原有全部指标。手机默认明细卡片，可切换表格；批量工具和订单操作在手机端默认折叠。
- 工作台支持“仅看异常”、上一项和下一项定位。修正窗口可按名称、编码、别名、规格搜索标准商品，保存后可直接处理下一项。
- “添加明细”“复制”在保存成功后才写入，取消不留空行；“拆分”将原数量拆成两行且合计数量不变，两行须重新核对。金额按行舍入，拆分前后可能因分币舍入有差异，需核对。
- 已确认订单默认只读，管理员或复核员点击“变更订单”后修改。没有实际变化的保存不改变确认状态；仅修改复核说明也保留确认；商品、数量、单价、单位、客户等实际变更须重新复核与确认。
- 勾选单行或筛选结果，可批量指定明细客户、设置整单交期、确认有效明细和导出。交期属于订单字段，窗口会提示整单实际影响范围；批量操作失败会整批回滚。
- 多客户订单卡片明确标注“含多个客户”，可主动“按客户拆单”。拆单形成独立草稿订单，保留共同原文及原进件关联，不自动替客户决定拆单规则。
- 商品资料页下方可维护客户联系人、地址、默认交期和商品协议价。新进件选择客户后回填常用信息，切换客户会更新此前自动填入的值，人工修改的信息继续保留；订单保留收货信息。协议价需在订单卡片明确应用，不自动覆盖历史成交单价。
- 更多筛选支持客户、来源、下单日期区间及交货日期；可按行业保存、载入常用条件。
- 导出窗口预览数量、金额、异常和前5行；支持全部、筛选、已确认、勾选范围，可选择原有20字段，下载CSV或真正的Excel .xlsx。Excel数量、单价和小计为数值单元格，方便计算。
- 图片可放大、缩小、旋转和复位。预览使用独立窗口，关闭后正在填写的修正表单仍保留。桌面与手机顶部均可查看保存状态并进入备份设置。
- 体验优化前源码备份位于上级“版本备份/体验优化前_20261022”；测试只使用隔离数据，不重置实际演示记录。
