# 重构演示版：修复对照与功能保留

日期：2026-10-22。对照依据：上级《业务与功能详细说明.md》V1.1中的G01—G23及原始源码快照。原分析文档描述旧Demo，本表描述本文件夹新版，两者适用版本不同。

## 一、原版问题逐项处理

| 编号 | 原问题 | 新版处理与验证要点 |
|---|---|---|
| G01 | 解析时切进件错绑客户 | 异步任务绑定行业、进件ID与取消令牌；切换即失效。实际UI测试切换后旧结果未写入新进件 |
| G02 | 解析时切行业回填旧结果 | 同一任务校验同时检查行业；每个行业单独保存资料，不跨行业回填 |
| G03 | 需求单位和商品计价单位混用 | 统一单位后换算；虾8斤=4kg，金额352元；不同维度无换算时留空数量，要求核实 |
| G04 | 豆腐3箱被填为30盒 | 使用商品包装因子12，正确输出36盒/126元；餐饮d1合计1798元，保留复核提示 |
| G05 | 异常可直接当正式订单导出 | 保留写入草稿和全量导出能力；正式确认拦截任何未解决明细，导出异常草稿须明确勾选 |
| G06 | 标新品后假装已解决、价格0 | “新品待建”继续待处理；填写档案后真实增加商品并回填；未定价使用null |
| G07 | 摘要漏算待复核 | 原文结果、顶部待处理、订单明细、筛选和汇总共用pending/errors判定 |
| G08 | 修改数量后无法结束复核 | 提供独立“确认明细”及修正窗口核对勾选；合法数据确认后退出待处理 |
| G09 | 切换行业丢数据 | 四行业分别保存；localStorage自动保存，可选SQLite；备份包含所有行业 |
| G10 | 删除后进件不能重录 | 删除/清空同步回退orderId及进件状态；动态统计同步回退；支持撤销且不覆盖之后新增资料 |
| G11 | 别名匹配后品名不统一 | 按标准商品编码回填标准名称；目录改名按编码更新显示，历史成交单价保留 |
| G12 | 无数量漏行、负数读成正数 | 不明确片段保留为待处理；负数拒绝；缺数量要求人工填写 |
| G13 | 无客户、日期和交期闭环 | 接收和编辑表单提供客户/下单日期/交货日期；识别客户标签与明天/周几；写入后主表与进件同步。非任意日期语义识别 |
| G14 | 无稳定来源和修改历史 | 每张订单关联sourceId；明细保留sourceId、原文位置、原始量单位、复核信息；记录修改前后值及操作人；CSV带来源字段 |
| G15 | 写入后残留候选报错 | 解析台通过同一context定位关联订单，候选、修正、确认指向有效明细，写入按钮变“查看订单”且不会重复建单 |
| G16 | 宽松数字读取吞掉非法字符 | 数量和金额整串校验；拒绝千位分隔编辑、字母、无穷大、科学计数和非法精度；错误输入回退 |
| G17 | 隐藏价格精度、行与总金额不一致 | 单价仅两位小数，整数分保存；BigInt逐行四舍五入至分后求和，页面与CSV共用同一算法 |
| G18 | 范围及中文千位误读 | 10-20斤不自动取上限；一千斤=1000斤；口语“十来斤”明确进入人工复核 |
| G19 | 数量片段生成伪品名 | “10斤”识别缺商品名，不把“斤”当商品；保留补录入口 |
| G20 | 重复原文高亮嵌套 | 解析记录每次出现的start/end位置，单次渲染不重叠区间；纸单空格差异按实际行范围处理 |
| G21 | 切换进件阶段残留 | 阶段由当前进件、解析结果及任务状态重新计算，接收未解析件不会继承上一件完成样式 |
| G22 | constructor等客户漏分组 | 使用Map汇总客户，不受对象原型属性影响 |
| G23 | “请复核”备注不触发待复核 | 复核、模糊、确认等提示加入issues并阻止自动确认；需用户核实后显式关闭 |

实现主要位于 `core.js` 的Store、rowFrom、updateRow、confirmOrder、summary、exportCSV与 `app.js` 的任务隔离、修正表单和事件处理。测试脚本及报告保存在tests，便于复查。

## 三、原版缺少的能力如何补齐

| 能力 | 本次交付 | 需要配置或范围边界 |
|---|---|---|
| 长期保存 | 浏览器自动保存＋可选SQLite、完整备份恢复 | 浏览器容量有限，服务与不同HTML入口的数据需备份迁移 |
| 商品维护及新品 | 档案、编码、别名、价格、规格、包装系数和建档回填 | 已有业务引用的计价单位禁止直接修改 |
| 订单和复核 | 独立订单号、主表、草稿/已确认、明细确认、变更回草稿 | 本机工作空间，无库存占用、支付及结算 |
| 来源与变更记录 | 稳定进件外键、全文、位置、修改前后、时间及操作人 | 演示日志不是不可篡改的合规审计系统 |
| 角色权限 | 本地服务会话＋服务端角色检查 | 演示账号共享同一工作空间，无企业多租户隔离 |
| 并发保护 | SQLite事务＋乐观版本，过期窗口拒绝覆盖 | 冲突需下载副本、重新载入并人工合并，非实时多人协同 |
| 图片/语音 | 真实文件接收、预览/播放、补录文本、可配置识别服务转发 | 外部OCR/ASR服务和凭据需要自行提供；预设案例明确标注 |
| 外部接收 | JSON导入＋令牌保护的HTTP进件接口＋外部消息去重 | 微信等平台需外部适配器，不冒充已接通微信 |
| 页面美观 | 统一浅色绿色主题、导航、卡片、状态、表格、弹窗、响应式与字体优化 | 已核对Edge桌面及390px窄屏，未宣称所有设备验收 |

## 四、金额基线

| 餐饮 | d1 | 5 | 1798.00 | 2 |
