# 巡场管理系统 · 重构版 Demo

本版本已于2026-10-22完成20项体验优化，调整对照与最新系统测试证据见《体验优化与系统测试报告.md》。

本版本根据原版双端 Demo 与《业务与功能详细说明》V1.1 重构，保留六个管理模块及移动巡更的业务入口，补齐本地持久化与跨端业务流程。原版文件、截图及分析文档未作改动。

## 启动

1. 双击本文件夹中的 **启动演示.bat**，保留打开的服务终端。
2. 浏览器自动打开管理端：[http://127.0.0.1:8793/](http://127.0.0.1:8793/)。
3. 从侧栏打开移动端，或访问 [http://127.0.0.1:8793/mobile.html](http://127.0.0.1:8793/mobile.html)。每个标签页独立登录，可同时演示多个角色。
4. 关闭服务终端或按 Ctrl+C 可停止服务；再次启动会保留数据。

当前电脑已安装的 Python 3.13 可直接运行，Windows x64 / Python 3.13 所需导出依赖已放入 vendor，无需 Node、npm 或在线 CDN。其他 Python 版本要求 3.10 以上，首次运行可能联网安装 requirements.txt 到本项目 .runtime，后续可以断网运行。

不要直接用 file:// 打开 static/index.html。业务页面需要本地服务。若 8793 被其他软件占用，可执行 `python server.py --port 8767`，改用相应端口访问。

## 建议演示顺序

1. 管理端登录 admin.chen，查看看板、计划日历、路线与点位。预置 6 条路线、35 个点位及最近 15 天任务。

3. 暂停、继续巡更；未巡完点位时结束必须填写原因，记录为“漏巡结束”。完整打卡后结束才记为“已完成”。
4. 从移动端上报异常。管理端在“异常处理”指派给孙工；另开移动端标签登录 repair.sun，接单并反馈；管理端复核结案，可重开或标记误报。
5. 张伟确认预置交接单；另一个移动标签登录 wanglei，由王磊确认接班。主管无法代签。
6. 管理端创建明日班次，选择人员和路线并完成每人路线分工；保存后生成任务并发送站内通知。模板可编辑、应用和删除。
7. 修改点位、调整路线顺序、新增人员，刷新核对保存结果。历史任务保留点位快照。
8. 在二维码模块选择尺寸、容错、附加信息，预览并下载 PDF、PNG 或 SVG。批量 PNG/SVG 输出 ZIP；单点可直接下载 PNG。
9. 统计报表选择期间与内容，导出可打开的 PDF、Excel、CSV 文件。
10. 在已登录且缓存完成的移动端使用浏览器离线模式，再打卡并刷新；恢复网络，查看“我的 → 离线记录与补传”。实际队列按本人身份、采集顺序补传，服务端按请求标识去重。

新增任务的时段请避开该人员已有未结束任务。初始化今日班次覆盖整天，因此新建班次建议选择明日。班次和任务都检查人员时间冲突；跨日班次按开始日期归属。

## 业务规则与数据口径

- 任务：待执行 → 巡更中 ↔ 已暂停 → 已完成 / 漏巡结束；管理端可取消未开始任务；已开始任务须填写原因后终止，已有执行和统计保留。执行操作仅限本人；存在另一项执行中任务时不能再开始。
- 打卡：按任务点位快照严格依序提交，同点位不重复；方式精确区分 QR、NFC、BOTH。打卡标识故障或停用后拒绝打卡；被检查设备异常不阻止到场检查。已有未结束任务使用的标识不能直接停用；现场受阻可由本人申请、主管审批后继续后续点位，跳过不算已巡或绩效豁免。
- 任务开始允许提前 10 分钟。时间来自带时区的采集时间，拒绝超过服务器未来 2 分钟、倒退到已有操作之前或超过 7 天的离线执行记录。
- 准时：采集时间 ≤ 计划开始时间 + 点位偏移 + 可配置容差，默认 10 分钟；既有打卡不会因设置变更重算。
- 点位完成率 = 有效打卡 / 应巡点位；任务完成率 = 完整完成任务 / 应执行任务；准时率 = 准时打卡 / 有效打卡。取消任务不计入分母，分母为 0 时显示 0%。
- 任务按计划开始日期归属；异常按创建日期归属；最近 14 天图表随报表期间变化。月度绩效按任务开始月份统计。
- 月度考核只取已结束或计划结束时间已到的任务，未到期任务单列；实际打卡数量独立保留并包含进行中任务。暂无考核数据时不显示零分惩罚。
- 月度评分 = 5 ×（50% 点位完成率 + 30% 准时率 + 20% 任务完成率），保留一位小数。排名依次按评分、打卡数、编号排序。移动端只返回本人名次，不暴露他人档案。
- 现场检查支持正常/异常结果；关键检查项由服务端校验；选择异常时与打卡一起生成关联事件。
- 异常：待处理 → 已指派 → 处理中 → 待复核 → 已结案；可标记误报或重开，每步保留本人、时间、说明。指派、复核、误报和重开须主管或总指挥；接单须被指派人。
- 交接：待交班确认 → 待接班确认 → 已交接。必须由双方本人依序勾选确认；不自动改变任务执行人。
- 班次保存即生成任务。重复支持每日、工作日、周一三五、自选星期，最多 90 天；整批冲突则回滚，避免半批写入。
- 路线顺序编辑后按预计用时均匀更新点位偏移，独立点位编辑可调整其偏移。已有任务保留点位名称、方法、顺序和计划偏移快照，现场健康与定位策略按最新配置检查。
- 全部数据 / 区域数据 / 本人相关数据由服务端过滤。菜单隐藏之外，写入与导出也校验权限。角色编辑不允许只开编辑、删除而关闭查看；内置总指挥不可删改以避免锁死管理入口。

## 设备与离线支持范围

**演示打卡**始终明确显示并保存来源，不会伪装为硬件验证。二维码是实际编码并带点位签名的链接；摄像头通过本地 jsQR 解码，NFC 通过浏览器 Web NFC 读取 NDEF URL/Text 记录。NFC 标签可写入与二维码相同的签名链接；本系统提供读取校验与标签档案备注，没有提供硬件写卡器。

摄像头、定位需浏览器授权及安全上下文，本机 localhost 可用；NFC 通常要求支持 Web NFC 的 Android Chrome、设备硬件与 HTTPS。桌面 Edge 不支持 NFC 时明确提示，不生成成功记录。默认服务只监听本机 127.0.0.1，实体手机跨设备访问需另行配置可达地址及 HTTPS。

定位仅在点位启用时请求并按配置半径核对，默认未启用。示意图展示可配置的点位位置，不是 GIS 地图、实时 GPS 轨迹或测绘底图。点位签名能校验本站标识，但链接可转发，演示版未提供生产级防代签、防定位伪造或不可篡改审计。

媒体支持最多 6 张 JPEG/PNG/WebP 图片及 1 段 MP4/WebM 视频。照片在浏览器缩小压缩至不超过 1MB，视频不超过 4MB；超4MB且30秒内时可尝试浏览器静音压缩为WebM，压缩后仍需不超过4MB。选择后预览、移除，随事件实际保存。手机文件选择器可根据设备提供拍照/拍视频入口。

离线需要先在线登录并缓存页面；不支持首次离线登录。离线仅暂存本人任务开始、暂停、打卡、结束、异常上报和消息已读。管理配置、指派复核等操作需要在线。缓存及队列保存在 IndexedDB，上传接口不缓存；队列记录按用户隔离、按原请求标识重放。遇到业务冲突保留失败项并暂停后续上传，用户可查看原始记录、重新补传或明确移除。清除浏览器站点数据会清除尚未上传记录。

## 文件与数据

| 文件 / 目录 | 用途 |
|---|---|
| 启动演示.bat / bootstrap.py | 启动与依赖检查 |
| server.py | 本地 HTTP、SQLite、业务规则、鉴权及实际导出 |
| static/ | 管理端、移动端、样式、交互、离线缓存与本地扫码库 |
| data/sentinel.sqlite3 | 首次运行生成的业务数据库，包括账号、会话、请求回执和审计 |
| vendor/ | 当前 Windows Python 3.13 依赖及许可证 |
| tests/ | 业务测试、浏览器联动测试、结果与截图 |
| 修复与验收对照.md | 原功能保留与 G01—G19 修复记录 |

备份时先停止服务，再复制 data/sentinel.sqlite3。需要全新演示数据时，先停止服务并把该文件改名留存，重新启动会生成当前日期样例；浏览器旧离线队列需先确认已上传或明确移除。不要直接在有未补传记录时替换数据库。

## 体验操作补充

- 巡更页默认突出当前点位，其他点位收起；正常检查可直接扫码/NFC，关键点位需先勾选检查项。结束入口位于“更多”，全部打卡后也显示结束提交入口。
- 维修与主管进入各自岗位工作台；站内消息可以直接进入关联任务、事件或交接单。
- 新建任务和班次可提前检查人员时间冲突；重复规则在高级设置中展开。班次保存时仍做完整冲突校验。
- 长表单关闭会提示保存草稿或放弃，重新进入需主动恢复；草稿不含密码与附件，照片/视频需重新选择。
- 报表明细20/50条分页；导出仍包含账号可见的完整范围，不受分页影响。
