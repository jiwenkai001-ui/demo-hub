# 交叉复核与演示验收报告

版本：V2.1　复核日期：2026-10-22　验收完成时间：2026-10-22T14:58:59+08:00

## 1. 结论与依据

本轮逐项对照原版业务与页面能力，发现并修复了展示字段、完成列表、手机导航、重置范围等遗漏，同时修复重启、跨日、错误恢复等稳定性问题。已确认的原版用户业务能力均已保留或增强，具体见[40项功能保留核对表](旧新版功能保留核对表.html)。

最终自动化验收 **53项通过，失败0、错误0、跳过0**；运行约115.8秒。包括26项业务/数据库测试、5项HTTP测试、22项浏览器测试。当前V2.1预览服务另有12项只读自检通过。

本结论以可取得的旧版前端源码和旧文档声明为边界：重新联网下载核对了11个前端文件，11个与原存档SHA-256一致。旧后端源码未获得，旧线上API曾404，不能声称旧后端所有内部规则均已逐字复刻。原版的固定接口样本截图不计入本轮运行验收。

有两处需要明确理解：新版增加商户登录和操作校验；旧文档声明的默认跨域改为显式--allow-cors可选模式，默认同源。同一系统的多设备访问无需跨域。接口结构与旧版不兼容，不能混用新旧前后端。

## 3. 业务闭环与数据联动

| 路径 | 本轮验证结果 |
|---|---|
| 顾客取号→商户等待→叫下一位→大屏及顾客更新 | 真实HTTP/SQLite通过；广播禁用时独立客户端轮询仍通过 |
| 叫号→过号→指定召回→多次重呼→完成 | 状态、过号/叫号次数、版本、当前号、完成记录一致 |
| 完成→再次取号 | 创建新号，旧号留档；不挤占仍在等待的号码 |
| 同设备重复/并发取号 | 仅保留一个有效号；不同设备并发号码唯一 |
| 两位店员同时处理同一号 | 仅一个提交成功，旧版本操作被拒绝；不会误处理下一位 |
| 响应丢失后重试 | 创建、叫号及完成幂等逻辑通过；叫号/完成浏览器模拟真实提交后丢ACK |
| 门店设置→顾客端 | 暂停、公告、接待时长与ETA同步；暂停仍可接待已有号 |
| 今日清空→各端→重启 | 当前号、列表、统计、我的号均刷新；编号不回退；不会重新自动填样本 |
| 全部营业日清空→各端 | 旧历史清除、场次改变、H001重开；保留门店设置/会话，不影响另一店 |
| 北京时间跨日→当前号/等待/过号/档案 | 旧有效号expired，留档结束时间，今日重新排号；手选历史日期不会被轮询覆盖 |
| 档案筛选/分页→CSV | 日期和状态过滤一致，导出包含筛选后的全量，UTF-8 BOM支持中文 |
| 断线、首次服务未就绪→恢复 | 错误可见，危险业务按钮禁用，恢复后无需刷新继续使用 |
| 实际服务关闭重开（同数据库/端口） | 原浏览器打开状态下自动恢复，设备号单和登录保留 |
| V2.0已有数据库→V2.1 | 原号单ID、登录会话及数据保留；新增字段自动迁移 |

另有固定随机种子的**1,000步独立业务模型对照**，包含两店、多营业日、重复取号、叫号/过号/召回/完成、暂停和两类重置；每步对照状态、次数、FIFO、总数、档案和号码唯一性。它属于26项业务测试中的1项，不另计为1,000项测试，也不等同生产压测。

## 4. 浏览器与界面验收

- 四页面中英文均在320、360、390、900、1440像素复核，整页无横向溢出。长表格在表格区域内横向滚动。
- 恢复服务类型、完整日期、过号次数、已完成记录；手机工作台可返回首页、打开顾客端、退出及展示二维码。
- 无BroadcastChannel、无crypto、存储受限时当前会话可运行；长期恢复仍依赖浏览器正常保存本地存储，清理存储/换设备视为新设备。
- 页面标题随语言切换，语言按门店/目录隔离记忆；门店名称与手写公告属于业务原文。
- 语音触发和重复播报次数经模拟API验证；语音接口抛错、复制失败不会中断业务。
- 浏览器测试收集未捕获pageerror并在每例结束断言为空，最终53项均通过。

## 5. 重置与演示样本的准确规则

| 操作 | 清理范围 | 编号 | 保留内容 |
|---|---|---|---|
| 清空今日数据 | 本店今日号单及业务动态 | 当日继续递增，不重复用号 | 历史日期、设置、会话、其他门店 |
| 重新开始演示 | 本店全部营业日号单、记录、计数 | 新场次从H001开始 | 设置、会话、其他门店、幂等账本 |
| 添加演示顾客 | 额外添加6位到本店当日队列 | 接续现有计数 | 所有原有数据 |
| 首次默认样本 | 首次空库启动添加12条 | 3完成、2过号、7等待 | 已有库不覆盖；手动清空后不自动再填 |

全部清空会保留原设置，因此原来暂停取号的门店仍需手动恢复开放。全部清空保留幂等账本，避免旧网络请求重试再次执行；场次ID变更会清理页面待重试操作。
