标智 AI · 纯前端 Demo 系统测试报告

测试日期：2026 年 10 月 28 日（Asia/Shanghai）。测试对象为当前纯前端演示工程，覆盖功能、业务逻辑、数据可靠性、安全性、性能、便利性及响应式布局。

本次确实发现了问题，并已修改源代码。首次新增的 15 组专项场景中，14 组复现异常；修复后继续扩展边界场景，最终 **34 / 34 组专项检查、9 / 9 组完整流程检查通过，共 43 组**。首次专项失败数量不代表整个系统的功能失败比例。

测试使用独立的 Edge 浏览器上下文和合成资料，不使用用户当前浏览器的配置或真实企业文件。

**首次复现并修复的主要问题**

P1 表示本演示中可能造成内容丢失、保存误判或关键业务状态错误；P2 表示需要修正的安全边界、功能或使用体验问题。优先级按当前演示的影响判断，不是公开网络漏洞评级。

| 编号 | 优先级 | 原问题及复现方式 | 已实施修复 |
|---|---|---|---|
| 01 | P1 | 本地项目、资料或风险列表混入 `null` 等异常记录时，页面可能白屏 | 加载时校验结构、隔离异常记录、恢复可用数据，并保留原始数据下载入口 |
| 02 | P2 | 被篡改的章节 HTML 可在打开编辑器时触发事件处理器 | 在渲染前通过惰性模板清理标签和属性，清除脚本、图片、事件及操作指令属性 |
| 03 | P2 | 进度字段直接拼接属性，可被构造成额外 HTML | 将进度转换为有限数字，并限制在 0—100 范围内 |
| 04 | P1 | 项目 A 的社保证明处理完成后，项目 B 的对应要求也显示匹配 | 按项目 ID 和检查类型查询状态；新项目拥有独立的示例检查事项 |
| 05 | P1 | 点击优化后继续输入，优化完成时可能覆盖最后输入的文字 | 优化结果合入前保存当前编辑；后台任务只修改原项目、原章节 |
| 06 | P1 | 浏览器写入失败后，编辑器仍显示“已保存” | 保存返回真实结果，失败时显示持续提示、备份和重试入口，不再误报成功 |
| 07 | P1 | 第二个窗口使用旧数据保存时，可能覆盖第一个窗口的修改 | 监听同源窗口的数据变化，并在写入前比较存储版本；冲突时停止写入，提供备份及加载最新数据入口 |
| 08 | P2 | 可选择不支持的扩展名或空文件 | 限制允许扩展名，拒绝空文件和超过 20 MB 的文件；选择和拖入使用同一校验逻辑 |
| 09 | P2 | 已选文件后上传区域消失，无法方便地重新选择 | 增加移除文件并重新选择的操作 |
| 10 | P2 | 解析过程中刷新后，待解析项目直接进入编辑器 | 待解析项目可重新启动模拟解析，浏览器历史切换时清理解析定时器 |
| 11 | P1 | 修改已完成标书后，项目仍保持“已完成” | 正文发生变化时退回编写状态，并同步界面中的状态和操作入口 |
| 12 | P2 | 全部章节保存后，项目进度仍停留在固定示例值 | 以已核验保存的章节计算进度；空章节不计入完成；增加提交审核和确认完成流程 |
| 13 | P2 | 弹窗初始焦点不在输入框，底层页面缺少操作隔离 | 设置合理初始焦点、Tab 循环、Escape 关闭、焦点恢复和背景 inert 隔离 |
| 14 | P2 | 1000 个项目一次性渲染全部表格行 | 项目及企业资料按每页 12 条渲染，搜索仍覆盖全部记录 |

章节与进度的注入测试通过主动修改测试浏览器的 localStorage 复现，需要攻击者能影响该存储内容；本轮未发现从现有上传入口直接远程注入这些载荷的链路。当前上传入口并不读取文件正文。

**扩展检查中一并修复或完善的事项**

- 风险标题在弹窗说明中统一按文本转义；编辑器粘贴和拖入内容按纯文本处理，并加入浏览器内容安全策略。
- 不能把缺少明确响应时间的正文直接标记为已修订；风险关闭后再将响应时间改回矛盾内容，会重新要求核验。
- 清空章节后刷新不再自动恢复默认示例；空白章节不能算作已完成，也不能据此提交审核。
- 保存后立即更新界面状态，避免底层状态已经变化、界面仍显示旧状态。
- 保留模板来源，显示资料过期状态，支持浏览器前进后退及刷新恢复项目和章节位置。
- 手机端保留投标截止日期、采购单位和预算等关键信息，不再因隐藏侧栏而全部不可见。
- Word 兼容导出将文本换行转为显式换行，防止多行粘贴内容在导出后合并。
- 增加本地图标，移除未实现的加粗、斜体工具栏展示，避免给出错误操作暗示。

**适用范围及尚未实现的能力**

1. 招标条款、页码、评分、草稿和风险仍为示例，没有真实 OCR、大模型调用、语义合规核验或行业专用生成能力。模板主要提供章节框架和项目分类，未做各行业内容质量验收。
2. 文件上传只保存名称及表单信息，没有保存或读取原件；扩展名和大小校验不等于恶意文件扫描或真实文档格式校验。
3. 没有账号鉴权、角色权限、多企业服务端隔离、加密存储和服务端审计。本次结果只适用于本地前端演示，不能据此认定满足商用安全要求。
4. 多窗口机制用于提示并阻止已检测到的旧数据写入，不是原子事务、自动合并或多人协同编辑方案。
5. 导出的是 Word 兼容 HTML `.doc`，不是原生 `.docx`。本轮验证了下载、文本、章节及换行，未在 Word/WPS 桌面端逐页验收排版。
6. JSON 备份可导出，当前尚未提供面向普通用户的备份导入恢复界面。浏览器本地数据仍可能因用户清理而消失。
7. 浏览器执行环境为 Windows 上的 Edge/Chromium；未覆盖 Safari、iOS 真机、微信小程序运行时和无障碍读屏软件的人工验收。

本轮全部用例通过，说明上述已覆盖场景中的问题已完成回归，不代表所有输入和运行环境均不存在缺陷。
