# 育苗苗生鲜静态演示模块

日期：2026-11-17；执行者：Codex。

- 本项目已由用户确认执行，范围为完整管理后台和学校下单端，纯静态 HTML/CSS/JavaScript，不添加业务后端或数据库。
- `DESIGN.md` 是唯一视觉约束；所有基础视觉在 `assets/styles.css` 集中维护。
- `assets/seed.js` 生成可重复初始数据；`assets/store.js` 是业务数据与状态变更入口；页面脚本仅编排 UI，不重复实现库存或财务规则。
- 各独立 HTML 页面加载本地公共脚本，无构建步骤，不使用远程 CDN。
- 共享数据需要同一浏览器与同一站点来源；使用附带静态预览入口。真实跨设备同步不在本版范围。
- 金额使用分整数；数量保留两位小数。订单保存价格和成本快照；新协议价不能追溯修改历史单据。
- 操作必须校验单据前置状态和数量；分拣扣库存，采购收货入库，取消不得重复返还库存。
- 演示 AI 和群资料收集必须明示模拟，文件预览不等于真实识别；打印只报告打开预览或进入队列。
- 经营报表统一根据订单、采购、库存与费用计算，净利润标为估算。
- 所有临时脚本、截图和测试数据位于 `.codex-tmp/`；不执行递归删除，需要移除时移入本目录 `delete/`。
- 同一次任务持续更新 `.codex-log/20261117165350_育苗苗静态演示需求与方案.md`。
- 没有 code-index、sequential-thinking、task-manager、Chrome DevTools MCP 或 Browser 插件；分别用 rg、文档内结构化分析与计划、可用 IAB 和本地 Playwright 替代，不虚构工具执行。
- 已完成交付验证：39 项业务测试、41 项浏览器检查、24 项静态检查。`npm test` 与 `npm run check` 不需要安装依赖。
- 对账按未入账来源生成补充账单；退货可能生成负数退款单，结算方向必须与账单符号一致，禁止把退款当普通付款累计。
- 浏览器筛选即时渲染并保持输入焦点；不要恢复未取消的延迟渲染，否则快速点击行操作可能被重新渲染吞掉。
- 初始订单 285 张；历史已完成采购和订单不能重复作用于当日期初库存。默认下单日期是次日，演示当天配送列表需主动改为业务日期。
- Windows 预览使用 TcpListener，避免 HttpListener 的 URL ACL；`preview.ps1` 因需兼容 Windows PowerShell 5.1 的中文注释，使用 UTF-8 BOM，其余文本为 UTF-8。
- 浏览器资源全部本地提供。生成图片服务曾返回 401，最终按已确认 DESIGN 实现，照片来源与许可在 README 中记录。
