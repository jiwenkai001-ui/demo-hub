# 育苗苗生鲜供应链 Demo

日期：2026-11-17；制作与本地验证：Codex。

完整电脑后台＋学校订货端，17 个独立 HTML 页面。交付内容为纯静态 HTML、CSS、JavaScript 与本地图片，不需要业务后端、数据库或在线 CDN。

## 打开方式

1. 完整解压文件夹，双击根目录的 `启动演示.cmd`。
2. 浏览器会打开 `http://127.0.0.1:8117/`。保持命令窗口开启，关闭窗口会停止本地预览。
3. 点击后台右上角“学校下单端”，或打开 `http://127.0.0.1:8117/school.html`。

Windows 预览入口使用系统自带 PowerShell，不需要安装 Node 或 Python，也不需要管理员权限。若端口已使用，可访问已运行的预览地址；多个独立 Demo 不应共用同一端口。

已安装 Node.js 的开发电脑也可以在项目目录运行 `npm start`，不需要 `npm install`。若使用其他端口，设置 `YMM_PREVIEW_PORT`。

通过静态托管或 Nginx 部署时，将本目录 HTML 和 `assets/` 一起提供即可。Node/PowerShell 脚本只用于本地发送静态文件，不提供业务接口。请通过同一个完整站点地址操作；不要混用 `localhost` 与 `127.0.0.1`，也不要以双击单个 HTML 文件的方式演示两端联动。

## 推荐演示步骤

1. 查看经营总览、客户、供应商和商品库，介绍 40 家学校、18 家供应商、2040 个 SKU 与两套协议价。
2. 打开学校端，选择“育才小学”，为黄心土豆、西红柿填写数量，点击“去结算”。演示当天完整链路时，将配送日期改为 **2026-11-17**；默认日期是次日。
3. 提交订单，进入后台“订单管理”搜索新订单号，点击“接单”，再点击“采购”。
4. 进入“采购管理”，按采购单确认收货，填写生产日期与保质期。多个供应商拆分采购时，需要完成全部关联采购单收货。
5. 进入“分拣管理”，核对或调整实称数量，确认出库；进入“配送管理”选择线路发车。
6. 回到学校端“我的订单”，点击“确认收货”。后台状态、学校收入成本与对账数据随之更新。
7. 进入“对账结算”，选择客户应收，生成本月账单，确认对账、登记结算；供应商应付以已入库采购为依据，并扣除退货。
8. 查看“经营报表”，切换学校利润和商品毛利，筛选学校、日期或本周，导出 CSV 或打开打印预览。

四个重点 AI / 管理场景：

- **AI 智慧录单**：供应商送货单和学校订货单两种模式。可上传图片/PDF 本地预览、运行演示识别、修正商品/数量/采购价，再确认入库或创建订单。
- **食安资料**：模拟收集缺失资料，审核、退回、分配学校、加入打印队列、预览资料与打印清单。
- **价格预警**：预置两条负毛利、一条低毛利样例，修改协议价后实时重算预警；历史订单保留成交价。
- **经营报表**：基于已签收订单计算学校/商品收入成本与毛利，展示演示配送、其他费用和报损分摊后的估算净利润。

## 数据与业务说明

- 业务日期固定为 **2026-11-17**，便于反复演示；近 30 天共 285 张初始订单，另有采购、批次、食安资料、14 张不同状态的初始账单和结算记录。
- 所有学校、供货商、联系人、地址和单据均用于演示；同名不代表真实客户关系。
- 每个浏览器、每个站点独立保存操作。同一浏览器的后台与学校标签页会同步；手机与电脑之间不会通过本静态版本共享数据。
- 首次业务操作时写入浏览器 localStorage。刷新可保留结果；“系统设置 → 恢复初始数据”可重新开始演示，“备份数据”可导出 JSON。
- 订单状态按“待确认 → 待采购 → 采购中 → 待分拣 → 待装车 → 配送中 → 已签收”推进。取消仅允许在开始采购之前。
- 采购收货增加库存，分拣按实称扣减库存；库存不足、重复收货/分拣/签收、件装商品小数数量均会被拦截。
- 库区调拨不改变总仓库存，换货记录等量出入库；退货产生供应商抵扣或退款账单。负数应付表示待退款金额。
- 对账仅收集尚未入账的来源单据；同月后续完成的单据可生成补充账单，已有结算记录不被重写。
- 金额以分计算，称重商品使用 kg，其余按商品计价单位；已有库存或业务历史的商品不可直接改变计价单位。
- 期初库存是当前业务日快照，历史已完成单据已包含在期初余额中；不能把全部历史采购再加入当前库存。

## 演示边界

- AI、群文件采集和设备联动均为可操作的模拟流程，未连接真实 AI、微信群、ERP、电子秤或 IoT 打印机。上传文件不会发送给外部识别服务。
- 点击打印会打开浏览器打印界面，不代表实体打印机已出纸。食安资料带有演示样例标识，不具备真实检测效力。
- 登记结算只修改本地演示账簿，不调用银行或支付服务。
- 净利润明确标注为估算值，配送费、其他费用阈值可在设置调整；实际经营口径需要正式系统进一步确认。
- 统计入口已按 demo-analytics 预留，配置未齐和本地/预览域名下均关闭。前端不包含管理 Token。

正式系统需另行提供现有 ERP API、OCR/AI 服务、企业微信会话存档和群覆盖权限、打印机厂商接口；若对接电子秤，需要设备协议。

## 本地验证与项目结构

```text
npm run check   # 24 项脚本语法与静态入口检查
npm test        # 39 项独立内存业务验证
```

- `assets/seed.js`：可重复生成初始关联数据。
- `assets/store.js`：库存、价格、订单、对账和本地持久化规则。
- `assets/ui.js`、`assets/styles.css`：公共布局、组件与视觉变量。
- `assets/views.js`、`assets/admin.js`：后台视图与事件编排。
- `assets/school.js`：学校端订货、购物车、历史订单和签收。
- `scripts/preview.ps1`、`scripts/serve.cjs`：两种本地静态预览方式。
- `tests/domain.cjs`：可移植的本地业务回归。
- `preview/`：最终桌面与手机预览图。
- `DESIGN.md`：唯一设计规范；`.codex-log/`：同一份完整方案、实现与验证记录。

浏览器已完成 41 项本地回归：全部 17 页、完整两端履约链、采购和库存、AI 两种录单、食安、正负账单结算、主数据维护、筛选、导出、打印调用、持久化与恢复。已检查 1440×900、1280×800 桌面和 390×844、430×932 手机，未发现脚本错误、失败资源或整体横向溢出。没有运行远程 CI。
