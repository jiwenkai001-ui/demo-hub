# 奥莱 Demo 模块说明

## 项目定位

- 本模块是“渭南奥莱运营管理系统”的可交互前端 Demo，用于客户展示与流程演示。
- PC 管理后台是主演示载体；移动端演示以同一页面中的手机框视图呈现，并支持会员端/商户端切换。
- 当前使用本地模拟数据，不连接真实后端、数据库、微信、POS、停车、支付或税控接口。

## 技术结构

- `src/App.vue`：统一壳层、PC 页面、移动端双角色视图与演示交互。
- `src/mock.ts`：商品、商户、会员和趋势数据的唯一标准演示数据源。
- `src/styles/index.css`：全局令牌、后台布局、表格、移动端和弹窗样式。
- `DESIGN.md`：项目唯一视觉与交互规范，修改页面时必须优先遵循。
- `src/main.ts`：应用入口及生产环境 Umami 条件注入。

## 业务边界

- 第一版重点演示经营总览、自营货品、商户与合同、会员运营和运营协同五个入口。
- 库存预警处理、商品创建、商户账单确认、会员定向发券、移动端角色切换是必须保持可操作的主流程。
- 移动端两个角色的四个底部标签都必须提供实际页面内容，禁止只切换选中态；会员端第二标签为“优惠权益”，商户端第二标签为“账单服务”。
- 优惠券领取、消息已读、未读角标和账单确认属于移动端演示状态，相关文案和数量必须同步更新；刷新演示数据后恢复标准起点。
- 状态只在当前前端会话内维护；刷新页面会回到标准演示数据。

## 已知注意事项

- `el-dialog` 的 `v-model` 必须绑定布尔计算属性，详情对象独立保存，避免 Element Plus 将对象状态写成布尔值。
- Umami 仅当生产构建、当前域名等于 `VITE_PRODUCTION_DOMAIN` 且同时提供脚本地址和 website id 时注入；localhost 和预览环境不得发送统计。
- 构建产物存在依赖体积提示，属于当前 Demo 的非阻塞项；后续可通过路由懒加载和 manualChunks 优化。
- 真正微信小程序、POS/停车/支付等接口需要单独的外部凭证、域名和服务端接口，当前不做接入。
