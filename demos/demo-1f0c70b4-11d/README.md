## OA 模块

包含办公工作台、审批中心、排班管理、考勤管理、任务协作、通知公告、制度资料、员工通讯录 8 个页签。

- 审批：请假、采购、加班、调班；新建、通过、带原因驳回、撤回、流转记录；重复处理拦截。员工费用报销统一从“院内费用报销”发起，历史 OA 报销保留查看和转入。
- 排班：前一周、本周、下一周示例，切换周与调整班次；请假通过自动标记对应日期，防止覆盖。
- 考勤：日期筛选、补录、迟到早退判断、跨日夜班；已有打卡与后批请假冲突提示核对。
- 任务：按负责人、状态、优先级、截止日期管理，支持创建、编辑及完成。
- 公告：发布、置顶、详情、已读状态；办公首页显示未读数。
- 制度：9 篇医院流程制度，包括医疗质量、院感、护理、药事、采购、财务、行政等；支持新增版本、搜索、阅读全文和下载 TXT。
- 通讯录：科室与员工搜索、岗位、职称、院内分机、专长。

初始 OA 内容包括 18 份审批、14 项任务、7 条公告及 9 篇制度资料。所有新增资料均为虚构演示内容。

OA 当前由院长/管理员演示角色处理。采购审批通过后仍需在进销存创建采购单并收货；调班通过后需负责人在排班页落实。公告已读对应当前演示管理账号。可在“接待与系统”切换5类角色，限制导航和业务写入；它是本地角色演示，没有真实登录认证、工资结算、真实支付或外部消息通知。

## 数据保存和兼容

原始 `demo/seed.js` 和 `data/pethospital.db` 保留；新增内容通过幂等迁移补入浏览器数据库。已有客户备注、业务记录及上传图片不会被初始化覆盖。首次读取也会保存升级结果，刷新后不会重复生成内容。

变更保存在浏览器 IndexedDB。同一个浏览器配置、同一种打开方式下，管理端和客户端共享数据；两个窗口的读写串行执行。刷新后保留。不同浏览器、不同电脑及 `file://` 与 HTTP 打开方式分别保存，不会自动同步。无痕模式关闭后不保留数据。

可在“接待与系统 → 备份与恢复”下载当前浏览器业务JSON。恢复前先校验数据库和关联关系，确认后自动下载恢复前备份。程序ZIP与浏览器业务JSON应分别保存。

建议始终从同一目录入口打开。新复制的文件夹或解压目录可能使用另一份浏览器本地数据。清除本项目的浏览器站点数据会恢复初始演示，请先确认不需要保留已做的操作。

## 九类角色验收与岗位使用

本轮增加真实岗位交接测试，说明见《九角色深度验收报告.md》。请在“接待与系统”上方切换演示身份，不同窗口可分别选择院长、前台、医生、财务和护理；宠主从右上角进入客户端。

- 前台：建档、预约、叫号、会员充值、权益服务、整理保险报销材料。
- 医生：病历、检验影像、医嘱、健康计划执行、医疗文书及出院确认。
- 财务：收退款、住院预交金、报销财务复核与付款、保险核定及赔付登记。
- 护理药房：入住照护、执行医嘱、监护、配发药与库存调拨；临床决策交由医生。
- 各员工可提交自己的办公申请和费用报销，处理本人任务、登记本人考勤；公告已读分别记录。
- 院长负责科室与大额审批、办公审批、排班、配置和备份；院长账号保留全流程演示能力。

角色切换与保险审核均为本地模拟。当前没有服务端认证、真实微信支付、保险接口或多设备实时服务，不能作为生产权限系统使用。已自定义的模块权限和账号绑定会保留；新增岗位演示员工仅在缺少相应岗位时补充。

新增验证：`node tests/role-journeys.cjs`。测试分别使用隔离窗口共享测试数据库，报告位于 `tests/role-results/report.json`，交付校验会核对该报告和当前源码哈希。
