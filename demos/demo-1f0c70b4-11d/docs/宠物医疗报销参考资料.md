## 建议在 Demo 中体现

1. 院内由前台选择宠主、宠物、就诊与对应已支付账单，录入保单资料并建立报销草稿。复用病历及费用清单，避免同一账单同时生成重复有效案件。
2. 分项显示保单及宠物身份资料、诊疗记录、费用明细、发票或付款凭证，另可登记检查报告及其他补件。区分系统关联记录和上传凭证；缺件需明确名称、原因及下一步。客户侧仅显示名称和进度，可向院内前台补充材料。
3. 演示状态：草稿 → 院内审核 → 保险审核（模拟）→ 待赔付 → 已赔付（模拟）；支持待补件、驳回和撤回。院内只协助准备，外部审核及到账由演示操作模拟，管理端和客户端均说明这一点。
4. 估算可采用虚构规则示例：`预估 = min(本次限额, 剩余可用额度, max(0, 已核对的合规费用 − 免赔额) × 赔付比例)`。费用按人民币分计算，先核对合规费用和排除项，再显示免赔、比例与上限的影响。缺少规则时显示待核对，不把未填限额当作零或不限额。该公式只是演示模型，真实产品的计费顺序和规则可能不同。
5. 单独显示账单金额、预估赔付、保险模拟核定和模拟到账；更新报销状态不等于医院退款或真实付款，不改动医院收款、会员余额或库存。可示例呈现已完成、待补件、未获核定等不同结果。
6. 客户端只返回本宠主的案件，收款账号只显示掩码，不展示医院内部备注或原始凭证。浏览器本地 Demo 仅使用虚构资料；不向保险机构发送数据，不接受实际理赔申请或支付指令。
