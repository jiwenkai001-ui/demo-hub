# 演示数据闭环与体验指南

更新：2026-11-11。电脑端与宠主端共用浏览器内的业务库，本轮增加 13 个演示场景、8 个推荐账号，以及可随时重新运行的 81 项数据检查。

## 从哪里开始

1. 在原文件夹打开 `index.html`，已打开的页面刷新即可，不需要清空数据。
2. 工作台点击“演示场景与数据”，或进入“行政协同 → 接待与系统 → 演示场景与数据”。
3. 点击场景中的病历、账单、报告、住院、报销等按钮，查看对应记录。
4. 点击“打开宠主端”，在同一浏览器打开 `client/index.html`。展开“使用演示账号体验”，选择对应宠主。
5. 两端完成签署、付款、护理、套餐核销或报销处理后，回到场景页点击“重新检查”，核对关联状态和金额。

电脑端和宠主端应在同一个浏览器配置中打开。当前是微信风格的本地 H5 演示；不同电脑、浏览器或配置之间不会自动同步。

## 建议实际演示的三条流程

### 小程序签署 → 住院护理 → 出院

选择周航账号，打开豆包的待签文书并签署。回电脑端打开相同住院记录，确认签署状态；完成护理医嘱并补充监护，再将预交金抵扣账单、完成出院核对，最后退回剩余预交金。原已出院的陈晨账号可用来对照完整结果。

### 免疫执行 → 批次库存 → 套餐余次

查看许宁账号的已完成免疫计划：本次免疫记录上的批号应与采购批次相同，库存减少 1，套餐次数核销 1，并生成下一次计划。继续执行另一条计划时，应选择对应犬猫种类的有效院内批次。库存不足、品种不符、重复执行都会被拦截，失败操作不会留下部分核销或扣库记录。院外历史免疫补录不扣院内库存。

### OA 报销 → 多级审批 → 付款与冲正

打开“OA 转费用报销与付款”的示例，核对来源 OA、费用单、票据、审批历史和付款。已付款状态下可填写原因进行冲正：费用单变为“已冲正”，净付款归零，OA 变为“已撤回”；重新发起后 OA 回到“待审批”。旧付款及审批历史保留，避免通过修改旧流水抹掉过程。

## 本轮数据整理

在原始演示种子保持不变的前提下，通过可追溯的版本迁移整理运行库。默认样例记录了 554 次修复，包含部分记录的多次修改，不能理解为 554 条独立错误。

- 恢复 225 条药品、检验、影像收费的来源关联，保留历史收费与实收金额。
- 补齐历史检验报告项目与归档、28 条缺失 SOAP，以及 152 条历史配发记录；历史配发归档不重复扣库存。
- 清除随机生成的耗材服药说明和药物剂量描述，修正原犬猫疫苗错配；历史样例不作为实际治疗处方。
- 依据连续库存台账校准原始随机批次，未分批库存明确标识，不编造生产批号和有效期。
- 校正没有核销依据的优惠券、营销统计、过期未到院预约和原卡缺失的历史会员支付。
- 对齐客户消费、就诊次数、会员余额、共享积分、OA 费用状态及候诊终态；后续每次成功写入继续同步。
- 新增可打开的虚构凭证、5 类专科完成记录、住院/预交金/签署示例、观察图卡和可播放短片、日结与分院销售。

## 数据检查与旧库升级

“演示场景与数据”底部显示 81 项只读检查，包括外键、来源单据、金额和数量、库存批次/流水、收退款、会员权益、住院护理、预交金、免疫、报销、附件、专科和日结。默认演示库覆盖 129 张业务与系统表，目前检查为 81/81 通过、0 条待核对记录；正常待办不计为异常。

迁移只执行一次，刷新不会重复添加家庭、场景或修复记录。修复前后的内容保存在库内，随“备份与恢复”导出的完整业务备份保存。新增场景使用独立演示笼位、演示分院及新 OA 申请，保留已有笼位维护状态、门店售价和待审批申请。

用户已修改的处方、券等记录不按原种子强制覆盖；不能安全修复的关联会显示“待核对”。例如旧库库存已经耗尽，无法完成原随机疫苗品种的成组库存校正时，保留原记录并报告，仍可正常打开页面。请根据实际业务核对，不能为消除提示而凭空补库存或虚构收款。
