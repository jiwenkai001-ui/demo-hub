## 业务逻辑分析

该产品主要覆盖宠物医院诊疗与门店经营：客户/宠物建档 → 预约挂号 → 问诊和体检 → 化验/影像 → 诊断处方 → 药房、治疗或住院 → 收银结算 → 回访、疫苗驱虫及会员复购。零售、库存、员工绩效、连锁调拨和经营报表为横向支撑。

从目录及官网设计可以看出五项核心能力：

1. **诊疗资料集中。** 病历、化验、影像、处方、文书及附件围绕宠物诊疗记录组织。
2. **院内与宠主协同。** 宠主微信端承接登记、预约、权益查询与报告查看；医生移动端承接预约、病历和回访。
3. **持续服务与复购。** 疫苗驱虫、套餐、计次卡、积分、回访和短信形成持续服务工具组合。
4. **多门店经营。** 店铺分析、商品独立和门店调拨反映连锁经营需求；具体共享范围仍需确认。
5. **规范化与效率。** 处方模板、剂量换算、专科病历、文书签署、设备接入和自动提醒旨在减少重复录入与纸张往返。

以上是模块关系分析，不等同于已实测所有数据实时联通。重点需进一步确认：处方与药房/库存扣减、设备报告与收费、住院医嘱执行与结算、会员权益与退款、调拨双端库存，以及绩效和经营报表的统计口径。

## 仍需向供应商确认的事项

- 是否有独立OA：请假、采购、行政审批、考勤、排班、任务、制度等；当前培训目录的“员工账号与权限”不足以证明。
- 是否有员工费用报销：明细、票据、财务复核、大额加签、付款及冲正；“收入支出记账”不足以证明。
- 是否有宠物保险理赔：保单、材料包、报案、核赔、保险公司接口、直赔/先付后赔；本次资料未见明确模块。
- 是否支持医保/商保之外的真实资金结算、电子发票、自动对账和完整会计科目；不可由收银支付介绍推断。
- 多助理如何关联诊疗、业绩如何分配；多卡如何关联客户与门店；连锁客户、宠物、会员及储值余额共享到什么程度。
- 哪些能力包含在基础版，哪些是独立付费模块、按量服务或设备对接费用。

“本次未见明确证据”不等于“软件没有该功能”。
