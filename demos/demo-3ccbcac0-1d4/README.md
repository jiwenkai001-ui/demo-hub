# 京麦源食品 · 纯静态交互 Demo

日期：2026-11-17；制作与本地验证：Codex。

## 打开演示

推荐通过静态 HTTP 服务运行，保证管理后台和客户订货端共享浏览器数据。

Windows 双击 `启动演示.cmd`，然后打开：

- 管理后台：http://127.0.0.1:8886/index.html
- 客户订货端：http://127.0.0.1:8886/client.html

启动脚本优先使用 Node.js 20+，也可使用 Python 3。没有安装依赖的步骤。

已有 Node.js 时可以执行：

```powershell
npm start
```

已有 Python 时可以执行：

```powershell
python -m http.server 8886 --bind 127.0.0.1
```

也可把整个目录放到 Nginx、IIS 或任意静态托管服务。入口是 `index.html`，不要只上传 HTML，需要一并保留 `assets/` 和 `js/`。

单独双击 HTML 可预览页面。浏览器对 `file://` 的存储隔离方式不同，跨页面数据联动请使用上面的 HTTP 地址。

## 演示包含什么

- 11 个后台页面：经营总览、客户管理、订单管理、智慧录单、配送与打印、商品资料、库存与批次、生产与成本、财务对账、额度与权限、演示设置。
- 手机客户订货端：专属价格、商品规格、购物车、下单、配送进度、历史复购、欠款、额度、账单导出与确认对账。
- 独立 A4 打印页面：线路配货汇总、客户送货单、简洁签收单、单价及金额列开关、页尾说明、无货隐藏。
- 初始虚构数据：42 款商品、420 家客户、241 笔订单、100 个原料/成品批次，以及生产、收款、损耗、盘点、历史对账和促销记录。日期按首次打开时的本地日期生成。
- 所有业务通过原生 HTML、CSS、JavaScript 与 localStorage 实现，无业务服务器、数据库、构建工具或 CDN 依赖。

## 建议演示顺序

1. 在经营总览查看订货、回款、库存和信用预警，点击待办进入对应列表。
2. 打开永辉超市客户详情，查看档案、欠款和专属价格；促销活动可按单客或客户类型配置。
3. 进入客户订货端，选购商品、修改规格、加入购物车并下单。
4. 返回后台订单管理，搜索刚生成的订单号；可编辑或取消待配货订单。
5. 在订单详情中开始配送、确认签收。库存出库、信用占用转应收、财务账单会同步更新。
6. 登记部分收款，再到客户端查看欠款和可用额度变化。
7. 在配送页面按线路筛选，切换品项汇总、打印线路配货单；送货单可隐藏价格和金额。
8. 在库存页面分次入库，或登记报损/盘点；在生产页面指定原料批次领料，登记成品产出，查看成本和溯源。
9. 在演示设置导出当前进度备份，恢复备份或重置初始状态。

## 可直接体验的特殊场景

- 超额锁单：客户“福满家鲜面店”（C0002）基础额度仅 20 元，存在未结欠款。下单时会拦截；切换业务经理可增加限时额度。
- 临时额度有效：C0003 有 24 小时授权；C0004 提供已过期的授权样例。
- 无货产品：P042“低盐荞麦面”初始库存为零。订单号末尾 0901 的草稿同时含有货和无货产品，可验证送货单筛选。
- 缺货下单可保存草稿，补货后确认。确认订单不会造成负库存。
- 智慧录单：粘贴“劲道细面 8袋，手工宽面 5袋，饺子皮 3袋”，识别后可修改商品、数量和规格，再生成订单。
- 财务支持逐单、客户、每日、月度、区域、收款、历史对账等视角；导出的是实际业务数据。

## 数据与计算口径

- 金额以整数分存储，库存重量统一为 kg，数量最多两位小数。
- 成交价先取客户专属价，再应用有效单客/群体促销；多个活动取最优惠折扣，不重复叠加。
- 草稿不占库存或信用；确认订单占用可用库存；取消释放；签收核减实存并生成应收。
- 信用已占用 = 未结清应收 + 未完成有效订单金额。签收前后不会重复记账。
- 另计损耗会额外占用并出库，不向客户计费；报损和盘点不能侵占已确认订单库存。
- 生产倍率 = 成品净重 / 原辅料实际投料净重；成本来自指定原料批次，按成品净重分摊。单位成本显示到分，分摊总额保持一致。
- 对账保存当次消费和欠款快照；后续回款不会改写历史确认记录。
- 数据保存在当前浏览器、当前站点；同源打开的后台和客户页会同步。换浏览器、设备或端口会使用另一份本地数据。
- JSON 备份包含客户、商品、库存、订单、生产、财务和操作记录；购物车与筛选条件是临时体验状态。重置会清理全部演示购物车。

## 演示边界与正式开发准备

- 客户、电话、地址、业务记录都是虚构演示数据；角色切换用于展示操作边界，不提供真实身份认证。
- 智慧录单采用本地文本规则模拟，正式 AI 服务需提供模型接口与授权。
- 多用户和跨设备同步需要正式后端与数据库；微信客户入口需对应账号与域名。
- 打印已验证浏览器预览、PDF 输出和列开关，实体打印机需在正式部署后按纸张与设备适配。
- 统计配置预留在 `js/analytics.js`：默认关闭，只有正式 HTTPS 域名、脚本地址和网站 ID 全部配置后才启用，不含管理 Token。
