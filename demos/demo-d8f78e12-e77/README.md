# 餐饮扫码点餐双端演示 Demo

## 项目说明
本 Demo 用于客户演示“店内餐桌扫码点餐 + 收银机/后厨双打印机同步出票”场景，包含两个系统：

1. 顾客小程序端（H5 模拟，微信手机号授权登录，无账号密码）
2. 收银机 Web 端（账号密码登录，登录页直接展示演示账号密码）

本版本重点演示：
- 菜单分类导航与总览卡片（更贴近美团等点餐体验）
- 菜品图文卡片展示
- 手机端底部常驻结算栏（滚动时始终可见）
- 扫码后自动模拟微信授权并直达点餐页
- 下单后跳转支付页，支持多支付方式模拟
- 支付成功后大提醒卡片（突出显示流水号、桌位号、取餐号）
- 支付成功后再通知收银机与后厨自动出票
- 餐桌二维码墙（每桌一个通用码，手机扫码直达点餐端）
- 会员中心预留模块（仅展示入口与信息卡，不做实质交互）

## 目录结构
- `index.html`：总入口（两端入口 + 餐桌扫码链接）。
- `mini-app.html`：小程序端页面。
- `cashier-web.html`：收银机端页面。
- `assets/shared.js`：订单数据、流水号、跨页面同步、打印任务共享逻辑。
- `assets/common.css`：全局主题与公共组件。
- `assets/mini-app.css` / `assets/mini-app.js`：小程序端逻辑。
- `assets/cashier-web.css` / `assets/cashier-web.js`：收银端逻辑。

## 本地预览
方式一（推荐）：
1. 在项目目录启动静态服务：
   ```powershell
   py -3 serve_demo.py --host 0.0.0.0 --port 8800
   ```
2. 浏览器访问：
   - 总入口：`http://127.0.0.1:8800/index.html`
   - 小程序端：`http://127.0.0.1:8800/mini-app.html`
   - 收银机端：`http://127.0.0.1:8800/cashier-web.html`
3. 在总入口底部“餐桌扫码入口（演示）”填写手机可访问地址（推荐局域网地址），自动生成二维码。

方式二：
- 直接双击 `index.html` 打开（部分浏览器跨标签页同步体验不如 HTTP 服务稳定）。

## 实时联动说明
- 手机端与收银端跨设备实时同步，必须使用 `serve_demo.py` 启动。
- 如果仅用 `py -3 -m http.server` 或直接双击 HTML，跨设备不会实时同步订单。

## 演示流程建议
1. 打开收银机端并登录（账号密码在登录页可见）。
2. 打开小程序端，输入手机号模拟微信授权登录。
3. 打开总入口的“餐桌扫码入口（演示）”，输入演示地址并生成每桌通用二维码。
4. 客户用手机微信或支付宝扫码进入对应桌位点餐页。
5. 在小程序端按分类选择菜品，进入“去结算（跳转支付）”。
6. 在支付页选择支付方式（微信、支付宝、云闪付、微信零钱、银行卡）并确认支付。
7. 支付成功后，收银端收到“已支付”订单并自动生成两份票据（收银联 + 后厨联），均显示：
   - 桌位号
   - 流水号
   - 支付方式
   - 菜品明细
8. 在收银端可补打小票、清空演示数据。

## 服务器静态部署
将整个 `restaurant-ordering-dual-demo` 目录上传到任意静态服务器（Nginx、对象存储静态站点、CDN 静态托管）即可访问演示。

部署后直接分享：
- `/index.html`
- `/mini-app.html?table=A01`（可用于餐桌二维码）
- `/cashier-web.html`

## 注意事项
- 本项目为纯静态演示，数据存储在浏览器 `localStorage`。
- 同步能力依赖同域名下的 `BroadcastChannel/localStorage` 事件。
- 关闭或清理浏览器站点数据后，演示订单会被清空。
- 二维码图片使用在线生成服务 `api.qrserver.com`，演示网络需可访问该域名。
- 手机扫码演示时，`127.0.0.1` 仅本机可见，需改为电脑局域网地址或公网可访问地址。

## 扫码进不去排查
1. 确认电脑和手机在同一局域网（同一 Wi-Fi）。
2. 先在电脑浏览器访问局域网地址是否可打开，例如 `http://192.168.x.x:8800/index.html`。
3. 总入口二维码配置中不要使用 `localhost` 或 `127.0.0.1`。
4. 若仍无法访问，检查系统防火墙是否放行 Python/8800 端口。
