保存与备份

数据使用 localStorage 保存在当前浏览器，存储键为 paw-farm-rebuilt-2026-v1。刷新和关闭页面后再打开同一地址可继续操作；其他标签页的更新会同步到当前页面。

在“账号与设置”可导出 / 导入 JSON 备份。导入会校验结构、类型、图片、金额与对象关联，替换前有确认提示；无效备份不会覆盖已有记录。存储写入失败时，本次订单与库存等修改不会提交。

文件路径、浏览器、访问协议或端口变化可能对应不同的存储空间；清理浏览器数据会删除本地记录。需保留时先导出备份。

演示与正式系统的边界

该版本提供单个本地演示账户，未接入真实登录鉴权、微信授权、后台数据库、支付、物流、短信、客服人工坐席、摄像头或视频平台。演示支付、商家发货、到店核销、领养审核、好友注册 / 首单和佣金结算均在界面明确标识；监护画面为本地插画示意，纪念卡为本地生成，不是现场摄影照片。

二维码实际编码订单与专属令牌，可在当前数据集内粘贴核销，但没有跨设备的服务器验真，也未集成摄像头扫码。分享会复制当前链接，文件地址适合本机查看；跨设备传播需要部署可访问站点并提供服务端数据。

本地事务可防止单次操作部分保存，跨标签页提供更新同步；它不具备多人并发锁、真实身份权限或支付回调安全性。原Demo没有明确的计费与营销规则，在新版中的演示默认值详见对照说明，正式建设时应由业务确认。

萌宠农场重构版：修复与功能对照说明

交付日期：2026-10-22。依据为父目录的《业务与功能详细说明》V1.1和原始Demo快照。原始快照与分析文档不被新版覆盖；本说明描述新实现，原文的缺口结论仍对应原版。

1. 重构范围

保留四个主栏目和27个子页面原有的业务内容与入口，使用统一数据模型重新实现。页面合并或位置调整以方便操作为目的，例如“疫苗记录”纳入按宠物区分的健康档案，仍可查看、登记和编辑，并扩展到驱虫和体检。

界面采用森林绿、奶油白与暖橙配色，本地动物和商品插画、统一图标、响应式卡片、侧边导航、手机底栏与原生模态弹窗。每次仅渲染一个主路由内容，避免收藏覆盖商品详情等多层页面冲突。

2. G01—G25逐项处理

编号 原版问题 新版处理与实际边界
G01 无保存、登录、用户隔离和后台 实现统一本地持久化、备份导入导出、恢复提示及跨标签页同步；真实登录鉴权、微信账户、多用户隔离和服务端不在本地版本中伪造
G02 活动价不一致 详情、预约、底部金额、订单都读取活动独立成人 / 儿童价，统一结算引擎计算
G03 预约未绑定信息 保存活动ID、日历日期、时段、人数、宠物、联系人、优惠与金额快照，表单与业务层双重校验
G04 余位固定，不占位 按活动、日期及重叠时段计算空间峰值；待付预占15分钟，超时、取消和退款释放，满员拒绝提交
G05 CSS假二维码，无核销 使用本地标准QR库生成真实编码；载荷绑定订单与令牌；未支付、失效及重复核销均拒绝。无摄像头扫码和服务端验真

G07 固定减15元 校验优惠券门槛、范围、有效期、周三条件及占用状态，实时计算积分余额与20%抵扣上限，配送费独立计算
G08 立即购买覆盖购物车 独立购买草稿与结算来源，不改写原购物车；只在购物车订单付款后扣减对应购物车数量

G10 订单按钮只提示 支持继续付款、取消、退款、退货、模拟发货 / 备货、确认收货 / 提货、评价、再次购买、活动改期与核销；非法状态拒绝操作
G11 发帖、评论、分享不落数据 内容、分类、话题、最多3张压缩照片与评论保存；分享实际复制链接，受浏览器限制时提供手动复制框
G12 点赞不保存且不同步 列表与详情从相同帖子数据渲染，点赞和关注持久化，样式由实际布尔状态决定
G13 知识错接与详情复用 独立知识列表、文章ID、正文、分类、搜索、阅读、点赞、收藏和正确详情链接

G17 地址、收藏、消息固定 地址增删改和唯一默认地址、下单地址快照、三类真实收藏、业务消息及已读状态
G18 统计、日期和状态不一致 统计来自订单 / 券 / 收藏等集合；日期相对当前日计算，券过期自动归类，健康计划采用同项目最新记录

G20 空车全选残留、页面栈混乱 空状态与选择值来自实际购物车；浏览器历史驱动返回，主内容统一渲染，弹窗使用原生dialog
G21 收藏覆盖商品详情 从收藏直接切换到商品路由，详情立即显示；返回恢复收藏页
G22 交叉点赞高亮相反 高亮按当前liked字段重绘，重复跨页操作不依赖旧DOM的class切换
G23 换活动沿用旧输入 进入新预约按活动初始化草稿与价格；金额重算和图片上传保留已填表单内容
G24 日期存相对索引、满员可提交 保存YYYY-MM-DD绝对日期，提交时再校验实际日期、时段、开始时间和剩余容量
G25 桌面按钮漂移、子页布局失控 主栏目、详情、表单与发布页使用同一自适应容器；桌面侧栏、手机底栏和固定控件适配各自视口

5. 状态与异常处理

业务 状态流转 主要限制
活动 / 美容 / 体检 待付 → 已付待使用 → 核销完成 → 评价 专属券只核销一次；活动与服务提前24小时可退款，活动还可改期
寄养 待付 → 已付待入住 → 核销入住 / 寄养中 → 照护记录 → 退房完成 → 评价 核销入住不会直接完成订单；照护日期须在入住至退房前一日之间

已完成的订单不在此Demo中提供普通退款入口，真实长期售后、分次退款和争议处理需服务端规则。演示工具允许模拟未来预约提前核销 / 入住及提前退房，便于现场演练，不代表真实门店可跳过服务时间。

异常值不会只依赖按钮禁用：业务方法会再次检查日期、号码、人数、时段、余位、库存、关联对象、优惠资格和当前状态。页面价格预览对超大或非法输入作显示保护，提交仍拒绝不合法值。

本地写入采用“读取最新快照 → 克隆 → 全部校验和修改 → 单次保存成功 → 发布新状态”。验证失败或空间不足不提交半成品。浏览器之间提供存储事件同步，但没有跨进程原子锁，不能用于真实多人抢购。
